01 • Fundamentos

Conceptos de Criptografía

Los 4 elementos esenciales del proceso criptográfico y las 3 grandes familias matemáticas.

01. Entrada

Texto Plano

Información original legible por humanos antes del procesamiento criptográfico.

02. Regla

Algoritmo (Cifrador)

Fórmula matemática pública. Su seguridad nunca debe depender de mantenerlo oculto.

03. Secreto

Clave Criptográfica

El parámetro secreto que controla la transformación. Sin ella, el mensaje es ilegible.

04. Salida

Texto Cifrado

Secuencia binaria que parece puramente aleatoria y protege los datos.

1 Sola Clave

Cifrado Simétrico

La misma clave cifra y descifra. Es ultra rápido, óptimo para bases de datos, discos y tráfico HTTPS.

Cifrado Clave K Texto Plano
Ejemplo: AES-256, Fernet Ultra Rápido
Par de Claves

Cifrado Asimétrico

Usa una clave Pública (para que cualquiera cifre) y una clave Privada (secreta para descifrar y firmar).

Mensaje Pública Token
Token Privada Mensaje
Ejemplo: RSA, ECC (Ed25519) Firmas
Irreversible

Funciones Hash

Genera una huella digital fija sin clave de descifrado. Sirve para verificar integridad y almacenar contraseñas.

"Texto" SHA-256 8c6976...
Sin retorno Integridad Pura
Ejemplo: SHA-256, Argon2id Integridad

02 • Mecanismo Interno

Funcionamiento de la Encriptación

El proceso secuencial paso a paso explicado de forma clara y directa para cualquier audiencia.

¿Cómo Opera en Python?

En Python, el proceso funciona tomando el mensaje original y pasándolo a través de una librería de seguridad junto con una clave secreta, lo que transforma el texto normal en un resultado revuelto e ilegible.

Esa librería se encarga de hacer todo el trabajo matemático por dentro para que no tengas que inventar nada complicado. Después, cuando alguien con permiso quiere leer el mensaje, vuelve a usar la misma clave para hacer el camino inverso y recuperar el texto original tal como estaba al principio.

ejemplo_pepem_wifi.py 
from cryptography.fernet import Fernet

# 1. Generar la llave secreta
llave = Fernet.generate_key()
caja = Fernet(llave)

# 2. Cifrar el texto original (en bytes)
secreto_oculto = caja.encrypt(b"Mi clave del WiFi es 1234")
print("Asi se ve encriptado:", secreto_oculto)

# 3. Descifrar y recuperar el original
secreto_abierto = caja.decrypt(secreto_oculto)
print("Asi vuelve a verse:", secreto_abierto.decode())
Salida de Consola (Python 3.12) Listo para ejecutar
$ python ejemplo_pepem_wifi.py
Presiona el botón verde "Ejecutar Código en Vivo" para ver la transformación criptográfica en tiempo real.
Nota técnica: Fernet genera un vector IV aleatorio en cada ejecución, por lo que el texto encriptado cambia siempre aunque el mensaje sea idéntico.

Fernet / AES

Backups en Cloud S3

Cifrado del lado del cliente antes de enviar copias de seguridad a AWS S3 o GCP. Cumplimiento normativo HIPAA y GDPR.

Librería: cryptography + boto3
JWT / HMAC

Tokens y Firmas Digitales

Autenticación stateless para microservicios. Las firmas criptográficas impiden que un cliente altere sus roles o permisos.

Librería: PyJWT / authlib

Control de Versiones (Git)

Esencial en el Mundo Digital

            

              La encriptación es esencial para proteger la información en el mundo digital. Con algoritmos como AES y RSA, y librerías como Cryptography y PyCryptodome, Python permite cifrar contraseñas, archivos y mensajes sin implementar matemáticas complejas desde cero.
            

          

          

            Pilar: Algoritmos Estándar & Productividad
          

        


        
        

          

            

              
            

            
Confidencialidad e Integridad

            

              El cifrado garantiza la confidencialidad, ya que solo quien tiene la clave correcta puede recuperar el mensaje, y la integridad, al detectar modificaciones no autorizadas. Esto es clave en la banca en línea, la mensajería privada y el almacenamiento de datos personales.
            

          

          

            Pilar: Privacidad + No Manipulación

              Sin embargo, la seguridad depende también de la gestión de claves: una clave expuesta compromete todo el sistema. Por eso conviene usar librerías reconocidas en lugar de crear algoritmos propios.
